# Implementation Notes

- Added `gradle/libs.versions.toml` defining a single source of truth for library versions to eliminate dependency issues. Added Kotlin, Compose, Hilt, Room, DataStore, JUnit etc., relying on up to date versions matching modern Android projects.
- Set up `settings.gradle.kts` properly scoping `google()` to prevent downloading issues or rate limit 429s.
- Made dynamic color false by default in `SafeStride5KTheme` to preserve the White/Blue Material 3 theme.
- Custom Workout Builder feature added to Home screen and Room DB (`CustomWorkoutEntity`, `CustomWorkoutIntervalEntity`, `CustomWorkoutDao`). Standard workouts and custom workouts seamlessly map to `TrainingWorkout` domain model and integrate with `TrainingPlanRepository` using an ID offset (>= 10000L).
- `HomeScreen` displays a "Build Custom Workout" feature card, quick access to C25K 9-week program, and a list of Saved Custom Workouts at the bottom.
- `WorkoutBuilderScreen` pre-populates Warmup (5 min) and Cooldown (5 min), allows adding custom Run and Walk intervals for any duration via duration picker dialog, and includes "FINISH BUILDING WORKOUT" and "SET WORKOUT NOW" action buttons.
- GPS and Workout foreground service active tracking implemented in subsequent active workout service phase.
- Phase 8 UX Polish implemented:
  - Extended `SettingsRepository` and `DefaultSettingsRepository` with DataStore persistence for `voiceCuesEnabled`, `soundCuesEnabled`, `vibrationEnabled`, and `onboardingComplete`, and connected `DefaultAudioHapticManager` to respect audio/haptic preferences dynamically.
  - Added `SettingsScreen` and `SettingsViewModel` (`ui/settings/`) supporting Miles/Kilometers unit toggling, Voice/Sound/Vibration toggles, Preferred Workout Days (3 days/week) and Program Start Date picker, and Reset Program / Clear Data confirmation dialog.
  - Added 3-step `OnboardingScreen` and `OnboardingViewModel` (`ui/onboarding/`) shown on first launch when `onboardingComplete` is false, with smooth `Crossfade` step transitions and animated progress indicator.
  - Added `LocationStatusBanner` (`ui/components/`) on `WorkoutPreviewScreen` and `ActiveWorkoutScreen` using `AnimatedVisibility` to handle permission-denied and GPS-disabled states gracefully.
  - Updated `ActiveWorkoutScreen` and `ActiveWorkoutViewModel` with a Cancel Workout Confirmation Dialog, Post-Workout Completion Celebration Dialog with New Continuous Longest-Run Personal Record badge (`"New Personal Record! 🏆"`), and accessibility / animation polish.
  - Added `asm` 9.8 in `gradle/libs.versions.toml` for Robolectric compatibility with JDK 25 bytecode.
- Phase 8.5 Advanced Running Features & Progressive Plan Extension implemented:
  - Standardized app-wide header and section card system (`AppHeaderBanner.kt`, `AppSectionCard.kt`, `AppSectionHeader` in `ui/components/`) with consistent `primaryContainer` highlights, `surfaceVariant` content cards, `errorContainer` alerts, and `SuccessContainerColor` celebrations across `HomeScreen`, `CalendarScreen`, `HistoryScreen`, `StatsScreen`, `SettingsScreen`, `WorkoutPreviewScreen`, `ActiveWorkoutScreen`, and `WorkoutDetailScreen`.
  - Added Open-Ended Free Run Mode (`WorkoutEngine.FREE_RUN_WORKOUT_ID = 0L`, `isFreeRun: Boolean`) counting up indefinitely from `00:00`, triggering audio/vibration split cues on every mile (`1609.34m`) or kilometer (`1000m`), and saving to `CompletedWorkoutEntity` with title `"Free Run"`.
  - Extended `DefaultTrainingPlanRepository` and `GenerateScheduleUseCase` with progressive volume expansion beyond 5K (+10% weekly running volume increase beyond Week 9) and configurable designated Long Run day in `SettingsRepository`, `SettingsScreen`, and `CalendarScreen`. Structured progressive weeks training cycle so that each 3-workout block begins after the designated Long Run day and culminates on `effectiveLongRunDay`, guaranteeing Workout 1 < Workout 2 < Workout 3 (Long Run) chronologically regardless of program start date or preferred day alignment.
  - Added current split tracking (`currentSplitDistanceMeters`, `currentSplitDurationMillis`, `currentSplitPaceSecondsPerKm`) in `WorkoutEngine` and displayed `"This Mile Pace"` / `"This Km Pace"` on `ActiveWorkoutScreen` and `WorkoutTrackingService` foreground notification.
  - Kept `displayedMonth: YearMonth` purely ephemeral in `CalendarViewModel` memory so scrolling months on `CalendarScreen` never modifies saved program start dates in DataStore.
  - Added `distanceMeters: Double = 0.0` to `CompletedIntervalEntity` and `CompletedInterval` (bumping `AppDatabase` version to 5), snapshotting cumulative distance at interval transitions in `WorkoutEngine` and displaying per-interval distance on `WorkoutDetailScreen`.
  - Updated `formatPace()` and added `formatPaceFromSecondsPerKm()` in `FormatUtils.kt` to cap maximum displayed pace at 300 min/mi (~186 min/km), returning `"--:--"` when stationary or moving very slowly.
- Phase 8.6 Active Run UX Polish, Open Exercise Modes & Accurate Program Progress implemented:
  - Removed the `"Open-Ended Count-Up Timer"` label and redundant top-bar `"FINISH"` button from `ActiveWorkoutScreen`, and restyled the bottom `"COMPLETE"` button as an `80.dp` `CircleShape` control aligned symmetrically beside Pause/Resume.
  - Added `averagePaceSecondsPerKm` to `ActiveWorkoutState` and throttled both `averagePaceSecondsPerKm` and `currentSplitPaceSecondsPerKm` refreshes in `WorkoutEngine` to `PACE_UPDATE_INTERVAL_MS` (3 seconds), while throttling `WorkoutTrackingService` running notification updates to 1-second/transition intervals.
  - Extended Open Exercise (`WorkoutEngine.FREE_RUN_WORKOUT_ID = 0L`) with initial `RUN`/`WALK` selection on `HomeScreen` (`initialType` query parameter in `NavGraph.kt` and `ActiveWorkoutViewModel`), live `RUN`/`WALK` switching via `WorkoutEngine.switchOpenExerciseType()` and `OpenExerciseSegment` tracking, and segmented persistence (`"Free Run"`, `"Free Walk"`, or `"Free Run & Walk"`) in `DefaultWorkoutHistoryRepository` so walk segments contribute only to `walkingSeconds` and never inflate `runningSeconds` or `longestCompletedRunSeconds`.
  - Updated `GetStatsUseCase` to include configured progressive extension weeks (`27 + progressiveWeeksExtension * 3`) in `ProgramProgress.totalProgramWorkoutsCount`, count only distinct completed official program workouts, and compute `currentWeekNumber` from the Sunday-aligned calendar start week (`SettingsRepository.programStartDate`).
